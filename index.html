How to Use

folder One scenario per story

Use # for one concrete case; another # for a materially different case. Use ## to name the sequence inside it. Select a story tab to see its diagram.

# Publish an application ## Release a change # Use an application ## Read a record

sticky_note_2 Assumptions

Use > for scope, assumptions and variations. A quoted annotation at the end of a step marks a local condition.

> [assumption] A record exists. > [note] This is the usual case.

person Actors and work objects

Actors are people or active systems, declared once per story. Activities are verbs. Braces name the thing handled or exchanged.

@User (person) @App (computer) User requests from App {Record} App returns to User {Record} "if authorised"

sync_alt Scope

These examples are digitalised domain stories that show a typical build or use scenario. They help discuss an architecture but do not replace a deployment diagram or security assessment. Check each actor, source, copy, access rule and trust boundary separately.
